# Screenshot and regression fixes — 0.1.5 (6)

This change follows the seven supplied iPhone screenshots and the independently reproduced 0.1.4 audit. It does not introduce addons or lossless playback.

## Changes and evidence

- **Content obscured by controls:** the shell reserves a viewport above the 56-point mini-player and native four-tab bar. Keyboard presentation hides the dock. A 402×874 fixture with 59/34-point safe-area insets verifies that content bounds stop above controls. Four full-shell renders are in `ui-review/iphone-*-dark.png`.
- **Player and lyrics:** smaller transport icons; the lyrics/queue dock omits volume to preserve reading space; title styles become compact in those panes. Removed lyrics-only black gradients that produced the rectangular seam and increased inactive-line contrast. Existing route pull/swipe and queue controls remain wired. `ui-review/lyrics-dark.png` shows the rendered lyrics pane.
- **Sheets:** compact neutral provider rows, a real spring return for cancelled sheet drags, reachable close controls, and a sheet surface painted through the bottom safe area. Titles retain the full width at large text sizes. Source switching retains pending/error/retry behavior.
- **Quality claims:** removed lossless labels from source and track details. Download preferences are upper limits, and activity displays the resolved source/bitrate only after resolution. Track details read the actual saved `audioBitrateKbps`/`audioCodec` keys.
- **Refresh error and charts:** inspected the live anonymous `FEmusic_charts` response for India. It exposed national music-video charts, Trending 20, seven language charts and artist rankings, but no song chart. `YouTubePlaylistParser.officialCharts` scopes chart shelves, excludes artist/non-playlist entries, retains provider order within groups and labels each group/country. Songs are never replaced by video suggestions. Sanitized endpoint/title fixture: `test/fixtures/youtube_charts_india.json`. Country requests send `formData.selectedValues`; concurrent requests coalesce per region, and late responses cannot publish trending tracks for a different region. An unavailable song chart is availability rather than a failed refresh. Chart Play loads the actual playlist and starts at index zero without shuffle.
- **Seek regression:** replaced the custom scrubber with a native slider plus track tap handling. Real pointer tests verify a 75% tap and cancellation without a seek. Fresh selections reset stale progress; source replacements preserve progress.
- **Queue race:** foreground recommendations capture selection revision and current queue entry, reject results after Clear Queue/source/selection changes, and deduplicate concurrent end-of-queue requests. Background insertion rechecks after each awaited insertion.
- **Download integrity:** exact known byte-count verification replaces the former 90% acceptance threshold. Tests reject both 9,500 and 10,500 bytes for a 10,000-byte transfer while preserving the previous file. The offline playback minimum is also checked before an atomic replacement, so a complete but unusably small transfer cannot destroy an existing copy. Last-resort YouTube search matches recording identity through `TrackMatcher` rather than accepting the first valid video ID.
- **iOS Favorite:** `audio_service` 0.18.19 explicitly disables `likeCommand` and has no native feedback implementation. A small Flutter channel bridges `MPRemoteCommandCenter.likeCommand` to the existing local favorites store, synchronizes active state and rejects stale track commands. Native callbacks are dispatched to the UI thread. Tests verify add/remove/idempotence, metadata preservation and stale-command rejection. The system controls whether and where the action appears; this is not a promise of a permanent lock-screen heart.
- **Distribution links:** README points to current release/download surfaces. The website reads the maintainer-selected shared `source.json` independently of GitHub counter requests; it no longer pins 0.1.0. No shared-catalog refresh is triggered by this change.

## Validation and limits

The final full Flutter suite passed with 164 tests. The rendered UI/source/download suite also passed with 58 tests. Static analysis and branding/source-feed validation passed. Native build status is recorded below when complete. Headless renders cover dark/light mode, small phones, large text, portrait/landscape player, and actual phone safe-area dimensions. See `ui-review/README.md` for render provenance.

This host has Command Line Tools but no full Xcode or iPhone simulator. Widget renders are fictional data and placeholder artwork, not physical-device screenshots. Native compilation is verified in the macOS GitHub build; device acceptance remains necessary for actual MPRemoteCommandCenter presentation, background audio transitions and network/provider behavior.
